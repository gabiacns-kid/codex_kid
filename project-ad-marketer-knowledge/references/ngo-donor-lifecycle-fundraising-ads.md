# NGO 후원자 생애주기 및 온라인 모금 광고 운영

Use this reference for Korean nonprofit and NGO fundraising proposals, especially when the advertiser already runs Meta/Naver ads, uses Naver Happybean, needs donor CRM and payment integration, or has a monthly paid-media budget around KRW 3.5-4.0 million.

## 1. 기본 판단

- 후원 광고의 핵심 전환은 `클릭`이나 `후원신청 시작`이 아니라 실제 결제 완료이며, 정기후원과 일시후원을 분리해 본다.
- CPA만 보지 말고 정기후원자의 유지기간, 첫 결제 성공률, 2회차 결제 유지율, 증액·재후원·휴면·해지까지 연결해 LTV/CAC 관점으로 판단한다.
- 예산이 작은 NGO는 다매체 분산보다 잠재 후원자 발굴용 Meta, 의도 포착용 Naver, 보유 후원자·친구 관계관리용 Kakao처럼 역할을 분리한다.
- Google Ad Grants 자격이 있다면 유료 매체 예산과 별도로 신청한다. 이는 월 최대 USD 10,000의 검색광고 현물지원 한도이며, 실제 소진을 보장하지 않는다.

## 2. 권장 매체 구조

1. Meta: 신규 잠재 후원자 발굴, 사례·현장·성과 중심 소재 테스트, 사이트 방문자 리타겟팅.
2. Naver Search: 브랜드·단체명 방어와 후원 의도가 분명한 검색 수요 포착. DIAD Pro로 순위·최대입찰가·CPC를 관리한다.
3. Kakao Message: 신규 냉타겟 확보 매체가 아니라 채널 친구, 적법한 광고수신동의 DB, 후원 단계별 메시지 운영 채널로 둔다. 감사·소식 발송만 계획한다면 유료 미디어 3순위로 예산을 고정 배정하지 않고 보유채널 운영으로 분리한다.
4. Google Ad Grants: 유료 예산을 잠식하지 않는 별도 검색 유입 축으로 신청·운영한다.

Kakao DB나 API 준비가 안 되었거나 기존 친구에게 감사·활동 소식만 보낼 계획이라면 세 번째 유료 매체를 억지로 키우지 말고 Meta와 Naver에 예산을 집중한다. Google Ad Grants는 별도 신청하고, 승인 전후에도 유료 3매체 분산보다 두 핵심 매체의 전환 데이터를 먼저 확보한다. 당근은 특정 지역·현장 캠페인, 네트워크/DSP는 충분한 방문자 모수와 리타겟 이벤트가 쌓인 뒤의 보조 실험으로 둔다.

## 3. 후원자 생애주기 구조

`광고 유입 → 캠페인 랜딩 → 후원 시작 → 결제 완료 → 감사·영수증 안내 → 활동 결과 공유 → 2회차 유지 → 증액·재후원·추천 → 휴면·해지 방어`

필수 데이터는 광고 소스·캠페인·소재, 캠페인/지원사업, 일시·정기 구분, 약정금액, 결제 성공 여부, 첫 결제일, 최근 결제일, 수신동의, 채널친구 여부, 메시지 반응이다. 광고 플랫폼 지표와 CRM 결제 결과를 후원자 또는 리드 ID로 연결해야 한다.

MRM 같은 후원자관리 시스템을 이미 사용한다면 새 CRM을 제안하기 전에 다음을 확인한다.

- 캠페인별 후원 신청 페이지 생성과 유입경로 저장 가능 여부
- GA4/광고 픽셀 또는 자체 트래킹 스크립트 삽입 가능 여부
- 정기·일시 후원, CMS·카드 등 결제 결과의 CRM 반영 여부
- 신규, 결제 실패, 증액, 휴면, 해지 상태값과 데이터 내보내기/API 가능 여부
- 광고성 정보 수신동의와 채널 메시지 발송 근거

## 4. Happybean 사용 원칙

- Happybean은 Npay 포인트·머니, 계좌·카드 간편결제 등 낮은 결제 마찰과 네이버 안의 신뢰가 장점이다.
- 공식 도움말에 따르면 Happybean은 별도 수수료를 받지 않고 결제 수수료도 보전하여 모금액을 100% 전달한다.
- 그러나 광고주가 소유한 도메인이 아니므로 임의의 GA4·Meta Pixel·Naver 전환 태그 설치를 전제로 제안하지 않는다.
- UTM을 붙여 클릭 유입을 구분할 수 있더라도, Happybean 내부 결제 완료를 광고 소재 단위로 자동 연결할 수 있다고 단정하지 않는다. Happybean이 제공하는 단체 보고서·유입 통계·내보내기 범위를 계정에서 확인한다.
- 따라서 Happybean은 네이버 검색에서 일시후원·소액 첫 기부의 마찰을 낮추는 랜딩으로 시험하고, 정기후원·후원자 생애주기 관리가 목적이면 자사 캠페인 페이지와 MRM 동선을 우선한다.
- 브랜드검색 링크에 UTM이 붙어 있는 것은 광고 클릭 URL의 식별 정보가 전달된다는 뜻일 뿐, Happybean 기부 완료가 검색광고 전환으로 회신된다는 뜻이 아니다.
- 자사 사이트에 설치된 Naver·GA4·Meta·BizSpring 태그는 Happybean 도메인에서는 실행되지 않는다. 공식적으로 제공되는 광고주용 전환 태그 설치나 광고 캠페인별 기부 완료 회신 기능이 확인되지 않으면 `해피빈 랜딩 전환 추적 가능`이라고 쓰지 않는다.
- Happybean 랜딩은 광고 클릭수와 기간별 모금액을 비교하는 제한적 측정 또는 홀드아웃·전후 비교에 활용하고, 키워드·소재별 완료 전환이 필요한 캠페인은 자사/MRM 후원 완료 페이지로 보낸다.

## 5. Kakao 메시지 운영 원칙

- 채널 메시지는 기존 카카오톡 채널 친구에게 발송한다.
- 브랜드 메시지는 광고성 정보 수신동의를 받은 전화번호 또는 앱유저ID 기반 브랜드 타겟을 사용하며, 현재 계정 자격·CBT 이용 가능 여부를 확인한다.
- 개인화 메시지는 후원 완료, 결제 실패, 캠페인 참여 등 행동 이벤트 발생 시 API로 개인화 발송할 수 있으나 개발·화이트리스트·동의 데이터가 필요하다.
- 단순 알림톡은 정보성 안내 범위에 한정한다. 모금 독려나 캠페인 홍보는 광고성 메시지 규정을 적용한다.
- NGO 메시지는 발송량보다 관계 훼손 위험을 먼저 관리한다. 기존 정기후원자에게 신규 후원을 반복 요청하거나 감정적 압박을 주면 채널 차단·친구 이탈·후원 해지의 계기가 될 수 있다.
- 기본 운영은 `활동 결과·감사 70~80% / 직접 후원 요청 20~30%`로 두고, 후원 직후에는 감사·집행결과 외의 추가 요청을 억제한다.
- 친구·일시후원자·정기후원자·휴면·결제실패·캠페인 참여자를 분리하며, 같은 메시지를 이메일·문자·카카오로 동시에 반복 발송하지 않는다.
- 월 발송 횟수는 업계 관행으로 확정하지 말고 낮은 빈도에서 시작해 친구 차단률, 수신거부, 클릭, 후원 유지율을 함께 본다. 가능하면 10~20% 홀드아웃을 두어 메시지를 받지 않은 집단과 해지·재후원 차이를 비교한다.

## 5-1. 태그 설치 흔적과 실제 추적의 구분

- 태그 탐지 도구에 BizSpring, GA4, Google Conversion Linker, Google Ads Conversion/Remarketing/User List/Audience, Google Marketing Platform, GTM, Meta Pixel, Daum/Kakao, Naver, YouTube가 보이더라도 각각이 독립적으로 정상 작동한다고 단정하지 않는다.
- Google 관련 여러 항목은 하나의 Google tag 또는 GTM 컨테이너가 여러 기능으로 탐지된 것일 수 있다. Universal Analytics는 종료된 레거시 태그일 수 있으며 YouTube IFrame Player API는 동영상 제어·측정 코드이지 후원 결제 전환 태그가 아니다.
- 반드시 광고 클릭 테스트 후 UTM·클릭 ID 유지, MRM 도메인 이동 시 세션 연결, 후원 완료 페이지의 이벤트 발생, 각 광고 관리자 전환 수신, 중복 발생 여부를 Tag Assistant·GA4 DebugView·Meta Test Events·Naver 전환 로그·BizSpring 보고서에서 확인한다.
- 외부 MRM 결제에서는 크로스도메인 설정, 콜백/완료 페이지, 스크립트 삽입 권한 및 결제완료 상태값을 확인한다. 태그가 공식몰 첫 페이지에만 있으면 후원 완료를 측정할 수 없다.
- 공식몰에서 MRM 링크에 `_gl`, `_ga`, `_gcl_au`, GA4 측정 ID별 쿠키 값이 붙는다면 Google linker가 크로스도메인 식별자를 전달하는 신호다. UTM이 MRM URL에 보이지 않아도 GA4 세션 소스는 이어질 수 있다. 그러나 목적지 MRM 페이지에 동일 GA4 속성이 로드되고 후원 완료 이벤트가 발생하는지는 별도 확인해야 한다.
- GA4 DebugView/Realtime에서 같은 사용자·세션으로 공식몰과 MRM `page_view`가 이어지는지, 원치 않는 `online.mrm.or.kr / referral` 새 세션이 생기지 않는지, 완료 시 `donation_complete`와 금액·일시/정기 구분이 수집되는지 검증한다.

## 6. 소재 원칙

- 불행을 과도하게 확대하는 감성 소재만 반복하지 않는다. `문제의 현실 → 단체가 실제로 한 일 → 후원 후 달라진 점 → 다음 참여 방법` 순으로 증거와 행동을 보여준다.
- 국내 복지 사각지대, 직접 운영 시설, 지원 이후 변화, 모금후기 등록률처럼 확인 가능한 근거를 활용한다.
- `후원금 100% 직접 전달`, `수수료 0%`, `국내에 전액 사용` 같은 문구는 적용 범위와 공식 근거를 확인한 경우에만 쓴다.
- 팔찌·굿즈는 첫 참여 장벽을 낮출 수 있지만 굿즈 목적 참여, 제작·배송비, 정기후원 유지 저하 위험이 있으므로 별도 캠페인으로 검증한다.

## 7. 예산 및 성과 판단

월 매체비 350만~400만 원의 초기 권장 비중:

- Meta 65~70%: 신규 후원자 발굴과 소재 학습
- Naver Search 30~35%: 브랜드·고의도 수요 포착
- Kakao Message: 유료 매체 예산이 아니라 보유채널 운영비로 별도 관리. 실제 후원 전환·결제복구 자동화가 준비된 경우에만 광고비 배분을 재검토

Google Ad Grants는 위 유료 예산과 별도 관리한다.

초기 핵심 KPI:

- 후원 완료 CPA, 정기후원 완료 CPA
- 랜딩 방문 대비 후원 시작률과 결제 완료율
- 첫 결제 성공률, 2회차·3회차 유지율
- 캠페인별 평균 후원금, 3·6·12개월 LTV
- 결제 실패 복구율, 휴면·해지율, 재후원율

전환량이 적으면 Meta에서 후원 완료 최적화가 안정되지 않을 수 있다. 이 경우 후원 시작을 보조 신호로 쓰되, 성과 판정은 실제 결제 완료와 유지율로 한다.

## 7-1. DSP를 활용한 생애주기 광고

- DSP 생애주기 운영은 카카오 CRM처럼 개인에게 메시지를 보내는 방식이 아니라, 사이트 행동·광고 식별자·허용된 CRM 매칭으로 익명 집단을 만들어 외부 웹·앱에서 배너/영상으로 재접촉하는 방식이다.
- 기본 세그먼트는 `캠페인 조회 후 미신청`, `후원 시작 후 미완료`, `후원 완료자 제외`, `최근 방문 휴면`, `CRM 재활성화 대상`으로 구성한다.
- 정기후원 완료자는 신규 후원 독려 광고에서 즉시 제외한다. 후원자에게 반복 모금 광고를 노출하면 광고비 낭비뿐 아니라 관계 훼손 위험이 있다.
- 일시후원자·휴면·장기후원자 같은 CRM 상태를 DSP에서 쓰려면 매체가 고객파일 또는 CRM/CDP 온보딩을 지원해야 하며, 광고·마케팅 활용 동의와 개인정보 처리 근거를 확인한다. 모든 DSP가 이를 지원한다고 일반화하지 않는다.
- NGO 후원 이력은 민감하게 받아들여질 수 있으므로 외부 매체에 세부 수혜 분야나 질환 관심을 노출하지 않고 중립적인 세그먼트명과 최소 데이터만 사용한다.
- DSP는 신규 후원자 확보보다 `검색·Meta 유입자의 재접촉`과 `후원 시작 이탈 복구`에 먼저 적용한다. 충분한 방문·이벤트 모수와 빈도 제한이 없으면 노출 과다와 높은 이탈이 발생할 수 있다.
- 후원 완료를 DSP에 회신하고 MRM에서 매체별 후원 유지율을 연결하지 못하면 DSP는 단기 전환 리타겟팅까지만 가능하며 진정한 LTV 최적화라고 표현하지 않는다.

### 7-1-1. 정기·일시후원 전환 구분

- DSP 스크립트가 후원 유형을 스스로 판별하는 것은 아니다. MRM이 `정기후원 시작·완료`, `일시후원 시작·완료`를 서로 다른 완료 URL, 이벤트명, 전환 태그 또는 이벤트 파라미터로 전달해야 구분할 수 있다.
- 매체가 사용자 정의 파라미터를 지원하지 않으면 `regular_donation_complete`, `one_time_donation_complete`처럼 별도 전환 태그·전환 라벨 또는 URL 규칙으로 나눈다.
- 정기후원 신청 완료와 첫 결제 성공은 다를 수 있으므로 가능하면 `신청 완료`와 `첫 결제 성공`을 별도 이벤트로 관리한다.
- MRM 도메인에 매체 태그를 설치할 수 없거나 완료 정보를 자사 도메인으로 돌려보낼 수 없으면 유형별 DSP 전환과 완료자 제외는 구현할 수 없다.

### 7-1-2. 모비온·타게팅게이츠 선택 기준

- NGO의 `신규 탐색 → 행동 단계별 리타겟팅` 구조에는 공개 소개자료상 RFM, DMP, 검색 관심, 브랜드 인게이지먼트, 리타겟팅 구성이 더 명시적인 타게팅게이츠를 우선 검토한다.
- 모비온은 일반 방문자 리타겟팅과 네트워크 도달을 단순하게 시험할 때 대안이 될 수 있다. 상품 피드·상품화 배너 강점은 비커머스 NGO에서는 상대적으로 활용도가 낮다.
- 이는 확정 성능 순위가 아니다. MRM 교차 도메인 태깅, 사용자 정의 전환, 세그먼트별 최소 모수, 고객파일 온보딩, 현재 최소 집행액·수수료를 두 매체에 동일 조건으로 확인한 뒤 최종 선택한다.

### 7-1-3. 운영 모수 판단 기준

아래 수치는 매체의 공식 최소 규정이 아니라, 식별자 손실과 세그먼트 분할 후 과소 모수를 고려한 실무 판단 기준이다.

- 최근 30일 전체 방문자 3천명 미만: DSP 분리 운영을 권하지 않는다. Meta·검색광고와 랜딩 개선을 우선한다.
- 3천~1만명: 전체 방문자를 묶은 단일 리타겟팅 정도만 시험한다.
- 1만~3만명: 후원안내 조회자와 후원 시작 이탈자를 2~3개 세그먼트로 나눌 수 있다.
- 3만명 이상: 신규 탐색과 복수 단계 리타겟팅을 병행할 여지가 커진다.
- 후원안내 페이지 방문자 1천명 미만: 관련 캠페인·활동 페이지 방문자와 합친다. 1천~3천명부터 별도 고려 세그먼트를 시험한다.
- MRM 후원 시작자가 최근 30일 200명 미만이면 60~90일 창으로 확대하거나 단독 운영하지 않는다. 200~500명은 하나의 이탈 복구군, 500명 이상이면 정기·일시 구분을 검토하되 각 군의 실제 식별 가능 모수를 확인한다.
- 후원 완료 30건 미만/월은 측정·제외 신호로 사용하고 완료 최적화를 과신하지 않는다. 30~100건은 방향 판단, 100건 이상은 완료 최적화 시험 후보로 본다. 정기·일시를 따로 학습시키려면 각 유형별 충분한 전환량이 필요하므로 월 50건 또는 최근 90일 100건 안팎을 실무상 최소 검토선으로 삼는다.
- 매체가 실제 광고에 사용할 수 있는 매칭 모수는 쿠키 동의, 브라우저 제한, 중복 제거, 교차 도메인 손실로 원시 방문자보다 작다. 최종 집행 여부는 매체가 산출한 `광고 가능 모수`로 판단한다.

### 7-1-4. 신규 탐색과 리타겟팅의 2단계 구조

- 기술적으로는 `신규 잠재고객 캠페인`과 `광고·사이트 반응자 리타겟팅 캠페인`을 분리할 수 있다.
- 신규 캠페인은 DMP·검색 관심·문맥 타겟을 사용하고 기존 방문자와 후원 완료자를 제외한다.
- 리타겟팅 캠페인은 `활동/캠페인 페이지 조회 후 이탈`, `후원안내 조회 후 미신청`, `MRM 진입 후 미완료`로 메시지를 달리하고 완료자를 즉시 제외한다.
- 그러나 월 총 광고비 350만~400만원에서 Meta가 이미 잠재고객 확보를 담당한다면 DSP 신규 캠페인은 역할 중복 가능성이 높다. 초기에는 Meta·Naver가 만든 전체 유입을 DSP가 재접촉하고, 증분 전환이 확인된 뒤 DSP 신규 탐색을 추가하는 순서가 효율적이다.
- DSP 고객파일 활용은 카카오 메시지처럼 개인별 발송이 아니다. 매체가 허용한 익명 매칭 세그먼트에 서로 다른 배너·영상 소재를 노출하는 방식이며, 고객파일 지원 여부와 개인정보·광고성 정보 동의 범위를 먼저 확인한다.
- 타게팅게이츠 리타겟팅 태그가 공식몰 전체에 설치되면 Meta·Naver·자연검색·직접유입 등 최초 유입 매체와 무관하게 태그가 실행된 방문자를 TG 식별자로 모아 재접촉할 수 있다. 유입원별로 나누려면 URL의 UTM·리퍼러 조건을 TG 세그먼트에서 지원하는지 별도 확인한다.
- MRM 완료 URL이 같아도 완료 시점에 서로 다른 이벤트명·파라미터·전환 라벨을 보낼 수 있으면 정기·일시후원을 구분할 수 있다. URL과 이벤트가 모두 동일하거나 MRM에 태그를 설치할 수 없을 때만 공식몰 행동 중심으로 제한한다.
- 아티스트컴퍼니 공식 자료실에는 2026년 `CRM 오디언스 타게팅` 소개서가 별도로 존재하므로 CRM 기반 오디언스 상품 자체는 확인된다. 다만 공개 다운로드가 제한되어 전화번호·이메일 해시 방식, 최소 매칭 규모, 허용 목적, 보관기간은 담당자 확인 전 확정하지 않는다.
- CRM 파일에 광고주 임의의 `고객유형` 열을 추가한다고 DSP가 자동 해석하는 것은 아니다. 매체의 정해진 업로드 스키마에 고객 속성 필드가 없다면, 광고주가 사전에 목적별 대상자를 분류해 `현재 정기후원자`, `일시후원자`, `정기후원 중단 6개월 이상` 등 별도 오디언스 파일·목록으로 업로드한다.
- 한 고객이 여러 목록에 중복될 수 있으므로 우선순위와 제외 규칙을 정한다. 예: 현재 정기후원자는 모든 신규후원 캠페인에서 제외하고, 정기후원 중단자는 재활성화에만 사용하며, 일시후원자는 정기후원 전환 캠페인 후보로 둔다.
- 기본 리타겟팅 태그는 `태그가 실행된 페이지 방문`과 익명 브라우저·기기 식별자 풀을 만드는 역할이다. 후원안내 조회는 URL 규칙으로 분류할 수 있지만 버튼 클릭·양식 시작·MRM 진입·후원 완료처럼 URL만으로 확정하기 어려운 행동은 별도 이벤트 태그 또는 매체가 지원하는 이벤트 매핑이 필요하다.
- Meta·Naver·자연유입 등 어떤 경로든 공식몰에서 TG 태그가 실행되고 추적 동의·식별이 가능하면 리타겟팅 모수에 포함될 수 있다. 태그 차단, 동의 거부, 쿠키 삭제, 다른 기기·브라우저 사용자는 누락될 수 있으므로 `모든 방문자`로 표현하지 않는다.

## 10. 2026-09-23 네이버 광고 대행 제안서의 측정 범위 교정

### 1) 새로 학습한 사실

- 더함께새희망 공식몰의 후원 CTA는 외부 MRM 신청 페이지로 이동한다. 네이버 광고 대행 제안서에서는 MRM을 `CTA 이후의 외부 목적지`로만 설명하고, 대행사가 MRM 데이터·후원자 상태를 관리하거나 통합 분석한다고 제안하지 않는다.
- 브랜드검색·파워링크·파워컨텐츠만 운영하는 범위에서는 광고비, 노출수, 클릭수, CTR, 평균 CPC, 평균 노출순위, 디바이스, 요일·시간대, 캠페인·그룹·키워드·검색어·소재별 성과를 기본 KPI로 삼는다.
- `정기후원`, `일시후원`은 실제 구매 가능 키워드나 검색 의도를 설명할 때는 사용할 수 있으나, MRM 연동과 후원 완료 데이터가 검증되지 않은 상태에서 후원 유형별 성과·유지율·LTV 지표로 확대하지 않는다.

### 2) 기존 지식에서 수정할 점

- 태그나 `_gl`·`_ga`가 확인된다는 이유만으로 네이버 광고 대행사가 후원 완료·후원 유형·금액·유지율을 리포트할 수 있다고 제안하지 않는다. 이는 별도의 측정 검증 또는 광고주 내부 데이터 제공이 있을 때만 가능한 범위다.
- 페이지 체류시간·스크롤은 네이버 광고 운영의 핵심 KPI로 제안하지 않는다. 특히 GA4 세팅과 데이터 해석 범위가 합의되지 않은 제안 단계에서는 제외한다.
- `키워드 승격` 같은 내부 판단 용어보다 `운영`, `관찰`, `제외`처럼 광고주가 이해하기 쉬운 표현을 사용한다.
- 네이버 검색광고만으로 후원자 LTV를 평가하거나 장기 유지 성과를 검증한다고 표현하지 않는다.

### 3) 실무 적용 원칙

- MRM 관련 확인은 후원 CTA와 랜딩 URL이 PC·모바일에서 정상 연결되는지 확인하는 수준으로 제한한다.
- 월간 리포트는 전체 광고비·노출·클릭·CTR·평균 CPC, 브랜드검색 소재·클릭영역별 성과, 파워링크 캠페인·그룹·키워드·검색어·소재별 비용과 클릭 성과, 디바이스·요일·시간대·평균 노출순위 차이, 파워컨텐츠 키워드·콘텐츠별 성과, 다음 달 변경 항목과 근거로 구성한다.
- 해피빈 랜딩은 간편 참여 경로로 검토하되, 광고 리포트에서는 연결 영역의 노출과 클릭을 중심으로 평가한다. 후원 완료를 광고 전환으로 직접 귀속한다고 쓰지 않는다.

### 4) 제안서/리포트 문장 예시

> 네이버 광고는 광고비·노출수·클릭수·CTR·평균 CPC·평균 노출순위와 실제 검색어의 적합성을 기준으로 운영합니다. 공식몰의 후원 CTA는 외부 MRM 신청 페이지로 연결되므로, 대행 범위에서는 PC·모바일의 링크 정상 작동 여부를 확인합니다.
