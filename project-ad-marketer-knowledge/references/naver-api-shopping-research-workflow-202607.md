# 네이버 API 기반 쇼핑·키워드 분석 운영 원칙 (2026-07)

## 적용 범위

네이버 쇼핑검색광고 제안 전 단계에서 상품군 후보, 유효 키워드, 검색 수요, 쇼핑 검색 결과, 쇼핑인사이트 추이를 정리할 때 사용한다. API 수집값은 광고 성과 예측이나 실제 광고 노출순위로 과대 해석하지 않는다.

## 1) 새로 학습한 사실

- 네이버 검색광고 키워드도구 API는 관련 키워드, PC·모바일 월간 검색수, 평균 클릭수, 평균 CTR, 경쟁정도, 평균 노출 광고 수를 제공한다.
- 키워드도구 API는 예상 CPC, 연령·성별 분포, 상품별 전환율·ROAS를 제공하지 않는다.
- 개발자센터 쇼핑 검색 API는 상품명, 가격, 판매처, 상품 ID, 브랜드·제조사·카테고리 등을 제공하지만 광고·일반 노출 구분이나 개인화된 실제 화면 순위를 제공하지 않는다.
- 쇼핑 검색 API 정확도순 응답에서 특정 상품이 확인된 순번은 `API 포착순번`으로만 기록한다. 이를 쇼핑검색광고 순위라고 부르면 안 된다.
- 쇼핑인사이트 API의 비율값은 요청한 상품군·키워드·기간 안의 상대지수다. 서로 다른 상품군 요청의 지수를 절대 검색량처럼 직접 비교하면 안 된다.
- 네이버 공식 공지 기준 개발자센터 쇼핑 검색 API는 2026-07-31 24:00 종료되고 2026-08-01부터 기존 이용자도 호출할 수 없다. 별도 대체 API는 제공되지 않는다고 안내됐다.
- Search Trend와 Shopping Insight는 NAVER API HUB로 이관된다. 기존 개발자센터 키 보유자는 안내된 유예기간 동안 기존 방식 이용이 가능하지만 신규 신청과 이후 운영 구조는 NAVER API HUB 기준으로 전환해야 한다.

## 2) 기존 지식에서 수정할 점

- `네이버 쇼핑 검색 API를 상시 호출해 경쟁 상품과 자사 노출을 자동 수집한다`는 운영안은 2026-08-01 이후 그대로 사용할 수 없다.
- 쇼핑 검색 API 결과에 자사 상품이 없다고 해서 실제 네이버 쇼핑 화면에 노출되지 않는다고 단정하지 않는다. 반대로 API 상위 포착을 광고 상위노출로 해석하지 않는다.
- 검색량이 큰 상품을 곧바로 주력상품으로 선정하지 않는다. 실제 선정에는 상품 가격, 리뷰 자산, 마진·배송비, 자사 상품 간 중복, 기존 매체의 상품 적합 전환 근거를 함께 사용한다.
- 다른 매체의 ROAS·PPC 구간은 네이버 예상 성과가 아니다. 네이버 운영 우선순위를 정하는 교차근거로만 사용한다.
- 상품군 수준에서 전환된 키워드라도 광고할 대표 상품페이지에서 실제 구매 가능한 옵션의 규격·구성·사용 방식과 다르면 운영 키워드로 승격하지 않는다. 반대로 대표 상품페이지에 숏핸들·롱핸들·밀대형·리필·올인원세트가 실제 옵션으로 등록되어 있다면 관련 키워드를 일괄 제외하면 안 된다. `상품명에 보이는 기본 구성`이 아니라 `구매 가능한 전체 옵션`을 먼저 확인한다.
- 쇼핑 결과의 전체 평균가·중간가는 리필 낱개, 본체, 세트, 대형·소형 상품이 섞일 수 있으므로 곧바로 가격 경쟁력 기준으로 사용하지 않는다. 동일 규격·구성·배송 조건의 비교군을 다시 만들어야 한다.
- 최대입찰가 기준 예상 CPC는 권장 입찰가가 아니다. 상품 가격, 공헌이익률, 전환율을 이용해 허용 CPC를 별도로 계산하지 않으면 매출은 발생해도 손실이 날 수 있다.
- 광고순위와 일반 쇼핑 노출순위가 모두 높은 검색어는 추가 광고의 증분효과보다 유료·자연 노출 간 잠식 가능성을 먼저 확인한다.

## 3) 실무 적용 원칙

### 2026-07-31까지

1. 상품 전체 목록에서 후보 상품군을 정한다.
2. 업체 상품에 없는 속성, 타사 브랜드, 저관련 키워드를 먼저 제외한다.
3. 검색광고 키워드도구 API로 월간 PC·모바일 검색수, 클릭수, CTR, 경쟁정도를 수집한다.
4. 쇼핑 검색 API로 검색어별 시장 규모, 가격대, 판매처 수, 자사 공식상품 포착 여부를 관찰한다.
5. 쇼핑인사이트로 최근 추이를 확인하되 같은 요청 범위 안에서만 비교한다.
6. 광고 주력상품은 검색 수요와 함께 리뷰, 가격, 마진·배송, 기존 전환 근거, 자사 SKU 중복 위험으로 평가한다.
7. 상품군 후보 키워드를 실제 광고 SKU에 맞춰 한 번 더 분류한다.
   - 직접 일치: 대표 상품페이지의 기본 구성 또는 실제 옵션이 검색 의도와 일치
   - 조건부: 옵션으로 구매할 수는 있지만 광고 이미지, 기본 선택값, 가격 표시 때문에 해당 구성을 바로 찾기 어려움
   - 제외: 다른 규격, 다른 사용 방식, 타 브랜드, 판매하지 않는 속성

### 옵션 통합 상품페이지 점검

1. `상품 1개 집중`을 `단일 SKU`로 표현하지 않고, 실제 구조가 옵션 통합형이면 `대표 상품페이지 1개에 광고 집중`으로 표현한다.
2. 키워드 제외 여부는 기본 노출 상품명뿐 아니라 옵션명, 옵션별 구성 수량, 옵션별 가격과 재고를 기준으로 판단한다.
3. 롱핸들·밀대형·리필·세트 검색어의 전환이 낮으면 즉시 제외하기 전에 해당 옵션이 첫 화면에서 보이는지, 옵션 가격과 구성을 이해하기 쉬운지, 선택 과정에 마찰이 없는지 확인한다.
4. 대표 가격 하나를 모든 옵션의 가격 경쟁력으로 일반화하지 않는다. 옵션별 판매가, 쿠폰가, 배송 조건과 공헌이익을 별도로 비교한다.
5. 옵션 검색 의도별 성과를 분리해서 보기 어렵다면 검색어 보고서, 제외검색어, 노출용 상품정보와 DIAD Pro 희망 키워드·순위 관리를 조합해 지출 방향을 통제한다.

### 2026-08-01 이후

1. 키워드 수요와 경쟁도는 검색광고 키워드도구 API를 유지한다.
2. 쇼핑인사이트는 NAVER API HUB 이관 상태와 인증 방식을 확인해 수집한다.
3. 상품·판매처·가격·자사 노출 검증은 네이버 광고의 쇼핑검색 노출현황보기와 공개 쇼핑 화면의 수동 표본 점검으로 전환한다.
4. 광고/일반 노출 구분과 연령·성별·지역 조건별 실제 노출은 광고 노출 진단 화면에서 확인한다.
5. 공개 화면은 개인화·시점·디바이스 영향을 받으므로 확인일, 기기, 조건, 검색어를 기록한다.

### 주력상품 선정 기준

- 검색 수요: 핵심 상품 적합 키워드의 PC·모바일 월간 검색수
- 매체 내 신뢰 자산: 리뷰 수, 판매처 구조, 가격 경쟁력
- 교차근거: 기존 G마켓·자사몰 등에서 확인된 상품 적합 직접 전환
- 예산 통제: 객단가, 예상 클릭비 부담, 마진·배송비
- 중복 통제: 동일 상품군의 유사 SKU 수와 자사 상품 간 경쟁 가능성

점수화가 필요하면 가중치와 수동 판단 항목을 공개하고, 점수를 성과 예측값이 아닌 우선순위 비교 도구로 표시한다.

### 수익성 입찰 기준

- 허용 CPA = 판매가 × 광고비 차감 전 공헌이익률
- 손익분기 CPC = 허용 CPA × 직접 전환율
- 손익분기 ROAS = 1 ÷ 공헌이익률

공헌이익률은 원가, 네이버 수수료, 쿠폰·적립, 배송비, 반품·CS 비용을 차감한 기준으로 계산한다. 실제 마진과 전환율이 없으면 예상 CPC 표의 최대입찰가를 그대로 운영안에 넣지 않고, 임시 테스트 범위라는 점을 명시한다.

### 자연 노출과 광고 노출의 중복 점검

1. 검색어별 일반 쇼핑 노출순위와 광고 노출순위를 같은 시점·기기·조건으로 기록한다.
2. 자연 노출이 이미 상위인 검색어는 광고 입찰을 낮춘 구간과 유지한 구간을 나눠 전체 주문·직접 광고전환·자연 유입 변화를 비교한다.
3. 하나의 검색어에서 쇼핑광고, 파워링크, 일반 쇼핑 결과에 자사 상품이 동시에 노출되면 매체별 직접 ROAS만 보지 말고 총매출 증분과 잠식 가능성을 확인한다.
4. 연령·성별·디바이스 구성은 초기 타겟 제외 근거가 아니라 관찰 신호로 사용한다. 광고계정의 실제 전환 데이터가 충분하기 전에는 과도한 연령·성별 제외나 가중치를 피한다.

## 4) 제안서·리포트 문장 예시

> 네이버 검색광고 키워드도구의 월간 검색수와 경쟁정도, 쇼핑인사이트의 상대 추이, 기존 판매채널의 상품 적합 전환 근거를 교차하여 주력상품을 선정했습니다. 검색량이 크다는 이유만으로 우선순위를 결정하지 않았으며, 가격·리뷰·상품 중복·마진과 배송 조건을 함께 확인해 최종 예산을 확정합니다.

> 네이버 쇼핑 검색 API의 포착순번은 정확도순 API 응답에서 확인된 관찰값으로, 쇼핑검색광고 순위나 개인화된 실제 화면 순위를 의미하지 않습니다.

> 타 매체의 ROAS 구간은 네이버 성과 예측값으로 사용하지 않고, 상품과 키워드의 판매 적합성을 판단하는 보조 근거로만 반영했습니다.

> 대표 상품은 하나의 구성만 판매하는 단일 SKU가 아니라 숏핸들·롱핸들·리필·세트 옵션을 함께 제공하는 통합 상품페이지입니다. 따라서 옵션과 일치하는 검색어는 제외하지 않고 의도별 성과를 구분해 운영하되, 옵션 노출과 선택 과정에서의 이탈 여부를 함께 확인합니다.

## 2026-07-27 계정 미열람 제안의 범위와 쇼핑 입지 종합분석

### 1) 새로 학습한 사실

- 제공 파일 기반 사실: 홈앤미 테이프클리너 분석에서는 네이버 쇼핑 검색 API의 상품 포착순번, 네이버 광고 노출진단의 특정 조건 광고순위, 일반 쇼핑상품 표본의 브랜드·상품 점유가 서로 다른 결과를 보였다. 세 값은 충돌하는 순위가 아니라 `API 응답`, `지정 조건 광고 진단`, `수집 표본 내 일반 노출`이라는 서로 다른 관찰 체계다.
- 제공 파일 기반 사실: 표시가격은 검색결과 중앙값보다 높게 보일 수 있었지만 대표 상품은 본체와 리필 10개 구성으로, 낱개·리필·본체·세트가 섞인 표시가격만으로 가격 경쟁력을 확정할 수 없었다.

### 2) 기존 지식에서 수정할 점

- 검색량이 가장 큰 넓은 키워드를 주력상품의 핵심 키워드로 자동 선정하지 않는다. `행거`, `옷걸이행거`처럼 이동식·스탠드형·저가형이 섞인 검색어에서는 주력상품 가격과 구조가 비교 대상과 크게 어긋날 수 있다.
- 상품 가격을 시장 전체 평균 하나와만 비교하지 않는다. 동일 상품도 키워드에 따라 함께 노출되는 상품군과 가격대가 달라지므로 검색 의도별 중위 가격과의 차이를 따로 본다.
- 리뷰가 많고 스토어 베스트에 포함된 상품이라는 이유만으로 모든 관련 키워드의 대표상품으로 쓰지 않는다. 상품 역할은 설치 방식, 단 구성, 커튼·선반 포함 여부, 공간 크기와 검색어별 가격대를 함께 보고 나눈다.

### 3) 실무 적용 원칙

1. 주력상품 선정표에 검색량뿐 아니라 키워드별 경쟁상품 유형, 중위 가격, 주력상품 가격 배수, 리뷰·판매 근거를 함께 둔다.
2. 넓은 키워드는 탐색용 저입찰 또는 제한 테스트로 두고, 상품 구조와 가격 차이가 작은 세부 검색어를 우선 운영한다.
3. 하나의 스마트스토어 안에서도 `대표상품 1개 + 검색 목적별 보완상품` 구조를 만든다. 각 상품이 맡을 키워드와 제외할 키워드를 함께 정해 자사 상품 간 중복을 줄인다.
4. 쇼핑 검색 API의 가격 표본은 옵션·배송비·쿠폰이 정규화되지 않은 관찰값임을 표시한다. 실제 입찰 전 동일 구성의 최종 판매가를 수동 확인한다.
5. 광고 노출용 상품명은 선택한 검색 의도에 맞춰 작성하되 공백 포함 25자 이내에서 모델명, 설치 방식, 커튼·선반 등 핵심 구성을 우선한다.
