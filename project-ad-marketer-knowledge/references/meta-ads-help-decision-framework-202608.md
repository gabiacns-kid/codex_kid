# Meta 광고 공식 도움말 기반 제안 판단 체계

확인일: 2026-08-26
기준: Meta 비즈니스 지원 센터의 광고 지원 허브 및 연결 공식 문서

이 문서는 Meta 광고 기능을 나열하기 위한 자료가 아니다. 광고주의 사업 목표, 전환 경로, 예산, 보유 데이터와 소재를 기준으로 **어떤 캠페인을 선택하고 무엇을 먼저 준비해야 하는지** 판단할 때 사용한다. Meta의 제품명, UI, 자동화 범위, 정책 및 제공 가능 기능은 자주 바뀌므로 제안서 확정 전 해당 공식 도움말을 다시 확인한다.

## 1. 공식 도움말의 범위

사용자가 제공한 링크는 단일 광고 가이드가 아니라 다음 주제를 연결하는 광고 지원 허브다.

- Facebook 페이지·Instagram·광고 관리자에서 광고 만들기
- 캠페인 목표, 타겟, 형식, 노출 위치
- 광고 보고서, 이벤트, Meta 픽셀, 전환 API
- 실험과 A/B 테스트
- 결제·청구·세금·지출 한도
- 비즈니스 포트폴리오, 계정 권한, 보안
- 광고 정책 및 제한 업종

따라서 제안서에서는 허브의 기능 목록을 그대로 옮기지 않고 아래 판단 순서를 따른다.

## 2. 제안서 판단 순서

1. 최종 성과를 구매, 상담신청, 견적요청, 메시지, 전화, 앱 행동, 매장 방문 중 하나로 정의한다.
2. 전환이 발생하는 위치를 웹사이트, 인스턴트 양식, 메시지, 전화, 앱 중에서 구분한다.
3. 해당 전환을 Meta에 정확히 전달할 수 있는지 확인한다.
4. 예상 CPA와 예산을 비교해 캠페인·광고 세트·소재를 나눌 수 있는지 판단한다.
5. 신규 고객 발굴과 기존 방문자 재접촉의 역할을 분리한다.
6. 업종 정책, 개인정보 처리, 결제 방식과 계정 권한을 확인한 뒤 집행안을 확정한다.

## 3. 목표 선택 원칙

- **인지도**: 도달·기억·영상 접촉 확대가 목적일 때 사용한다. 구매 성과를 직접 보장하는 캠페인으로 표현하지 않는다.
- **트래픽**: 랜딩페이지 조회나 링크 클릭을 늘리는 데 적합하다. 클릭이 많다는 이유만으로 구매·유효문의 가능성이 높다고 판단하지 않는다.
- **참여**: 게시물 반응, 영상 시청, 메시지 등 선택한 참여 행동을 늘릴 때 사용한다. 참여 지표와 매출을 동일시하지 않는다.
- **잠재 고객**: 인스턴트 양식, 웹사이트 양식, 메시지, 전화 등 실제 제공 경로를 명시한다. 문의 수와 함께 유효문의율·상담연결률·견적발송률을 평가한다.
- **앱 홍보**: 앱 설치나 앱 내 행동이 최종 성과일 때 사용하며 SDK/MMP와 앱 이벤트 준비를 먼저 확인한다.
- **판매**: 웹·앱 구매 또는 카탈로그 기반 판매에 사용한다. 구매 이벤트, 상품 데이터, 가격·재고·랜딩 일치가 준비돼야 한다.

목표 이름이 같아도 전환 위치와 최적화 이벤트가 다르면 운영 방식과 성과 해석이 달라진다. 제안서에는 목표명만 쓰지 말고 `전환 위치 + 최적화 행동 + 랜딩 경로`를 함께 적는다.

## 4. 예산과 계정 구조

- Meta 광고는 캠페인-광고 세트-광고의 구조로 운영한다. 목표는 캠페인, 타겟·예산·노출 위치·일정은 주로 광고 세트, 문안·이미지·영상·링크는 광고 단위에서 결정된다.
- 소액 예산을 여러 목표와 다수 광고 세트에 나누면 각 조합의 판단 표본이 부족해진다. 초기에는 핵심 목표 1개, 광고 세트 1~2개, 구별 가능한 소재 가설 몇 개로 시작한다.
- 예산은 임의의 최저 금액보다 예상 CPA, 전환 지연, 필요한 검증 건수를 기준으로 판단한다.
- 성과가 흔들린다는 이유로 예산·타겟·최적화 이벤트·소재를 동시에 바꾸지 않는다. 변경 전후의 원인을 구분할 수 있게 순차 적용한다.
- Meta가 제공하는 자동화 기능은 예산 배분과 도달 확장 수단이다. 랜딩 경쟁력, 상품성, 리드 품질을 대신하지 않는다.

## 5. 타겟 판단

- 관심사는 해당 업종에 관심을 보였을 가능성을 나타내는 신호이며 실제 직업, 구매 의도, 소득 또는 계약 가능성을 증명하지 않는다.
- 맞춤 타겟은 웹사이트 방문, 고객 목록, 앱 활동, Meta 내 참여 등 합법적으로 사용할 수 있는 소스를 기준으로 설계한다.
- 고객 목록은 수집 동의, 개인정보 처리방침, 업로드 권한과 데이터 품질을 먼저 확인한다.
- 유사 타겟이나 자동 확장은 좋은 원본 데이터가 있을수록 의미가 있다. 저품질 문의를 원본으로 확장하면 저품질 패턴도 확대될 수 있다.
- 신규 계정에서 지나치게 좁은 관심사 조합만 고집하지 않는다. 넓은 타겟과 명시적 관심사 타겟을 구분해 테스트하되, 예산이 작으면 하나의 핵심 가설부터 검증한다.
- 주택·고용·신용 등 특별 광고 카테고리와 제한 업종은 일반 타겟 원칙을 그대로 적용하지 말고 최신 정책과 실제 설정 가능 범위를 다시 확인한다.

## 6. 노출 위치와 소재

- Advantage+ 노출 위치는 Facebook, Instagram, Messenger, Audience Network 등 가능한 위치에서 시스템이 예산을 배분하도록 하는 방식이다. 모든 위치의 트래픽 품질이 동일하다는 뜻은 아니다.
- 자동 노출 위치를 기본 검토하되, 지면별 클릭·랜딩페이지 조회·전환·유효문의 품질을 분해해 판단한다.
- Meta의 2026 Audience Network 형식 업데이트는 클릭률 상승과 클릭 후 전환율 하락이 함께 나타날 수 있음을 공식적으로 안내했다. CTR만 보고 해당 지면을 확대하지 않는다.
- 피드용 1:1 또는 4:5, 스토리·릴스용 9:16처럼 주요 지면에 맞는 비율과 안전 영역을 준비한다.
- Meta는 릴스에서 9:16 세로 영상, 오디오, 안전 영역 안의 핵심 메시지를 권장한다. 이는 보편적 성과 보장이 아니라 공식 권장 제작 방식이다.
- 정지 이미지도 집행할 수 있지만, 릴스 성과를 핵심 근거로 제안할 때는 세로 영상 또는 적절한 모션 소재 준비 여부를 밝힌다.
- 소재 수는 많을수록 좋은 것이 아니다. 예산이 작은 계정은 문제 제기, 기능 시연, 후기·증거, 혜택 등 서로 다른 가설을 구분할 수 있는 수로 제한한다.

## 7. 측정 설계

- 웹사이트 전환은 Meta 픽셀을 기본으로 검토하고, 서버에서 전환 데이터를 보완할 수 있으면 전환 API를 함께 검토한다.
- 픽셀과 전환 API를 병행할 때 동일 이벤트 중복 집계를 막기 위한 이벤트명·이벤트 ID 일치와 중복 제거를 개발 단계에서 확인한다.
- 페이지 조회, 버튼 클릭, 양식 시작, 양식 제출, 구매 완료를 구분한다. 최종 성과가 문의라면 단순 버튼 클릭을 문의 완료로 보고하지 않는다.
- 리드 사업은 광고 관리자 전환 수만 보지 않고 리드번호 또는 CRM 상태로 상담연결, 유효문의, 견적, 계약을 광고 정보와 연결한다.
- 인스턴트 양식은 구축이 빠르지만 낮은 입력 장벽 때문에 리드 품질이 낮아질 수 있다. 자격 질문, 확인 화면, 빠른 후속 연락으로 관리한다.
- 메시지와 전화는 대화 시작·통화 시도와 실제 상담 완료를 구분한다. 플랫폼 내 지표와 영업 기록을 함께 본다.
- 오프라인 결과를 회수할 수 있는 광고주는 계약·매장구매 등 후속 데이터를 전달해 단순 리드 수가 아닌 가치 있는 결과를 학습시키는 방향을 검토한다.

## 8. 실험과 성과 해석

- A/B 테스트는 한 번에 하나의 핵심 변수만 비교한다. 타겟, 소재, 최적화 이벤트를 동시에 바꾸면 원인을 판단하기 어렵다.
- 클릭률·클릭당비용은 광고 반응 지표다. 구매·유효문의가 목표라면 전환율, CPA, 매출, 유효문의율과 함께 본다.
- 어트리뷰션 결과는 설정된 기여 기간과 플랫폼 측정 방식의 영향을 받는다. GA4·CRM·주문 데이터와 숫자가 다를 수 있으며, 어느 한쪽을 자동으로 정답으로 두지 않는다.
- 전환 지연이 긴 업종은 집행 직후 며칠의 수치로 결론을 내리지 않는다.
- Meta가 발표한 평균 성과·사례 연구 수치는 참고 자료다. 광고주의 업종·국가·예산·소재·랜딩에 동일하게 재현된다고 약속하지 않는다.

## 9. 결제·계정·정책

- 광고비, 대행 수수료, 부가세, 소재 제작비를 분리해 광고주 부담액과 실제 매체 집행액을 표시한다.
- 결제 수단, 청구 방식, 지출 한도, 세금 처리와 월간 인보이스 자격은 계정·국가·결제 설정에 따라 달라질 수 있으므로 실제 광고 계정에서 확인한다.
- 대행사는 광고주의 비즈니스 포트폴리오와 광고 계정 권한을 받아 운영하는 구조를 우선한다. 여러 광고주의 비용을 하나의 대행사 결제수단에 무리하게 집중하지 않는다.
- 건강, 개인적 특성, 금융, 주택, 고용, 정치·사회 이슈, 도박, 암호화폐 등은 최신 광고 표준과 국가별 제한을 확인한다.
- 광고 문구에서 사용자의 건강·재정·개인 특성을 단정하거나 열등감·공포를 직접 자극하지 않는다. 과장 효능, 보장 수익, 오해를 부르는 전후 비교도 별도 심사 위험으로 검토한다.

## 10. 광고주 상황별 적용

### 웹사이트가 없는 상담형 광고주

- 인스턴트 양식 또는 메시지형 리드를 우선 검토한다.
- 입력 항목을 최소화하되 유효성을 가릴 질문을 포함한다.
- 영업팀 연락 속도와 미응답 처리 기준을 운영안에 넣는다.

### 웹사이트가 있는 B2B 광고주

- 웹사이트 양식 제출을 주 전환으로 두고 픽셀·전환 API·UTM·CRM 연결을 준비한다.
- 검색 수요가 작은 경우 문제 인식 소재로 잠재고객을 만들고, 방문자 재접촉과 사례 콘텐츠로 의사결정을 보조한다.

### 쇼핑·전자상거래 광고주

- 구매 이벤트와 카탈로그 품질을 먼저 확인한다.
- 신규 고객, 방문자, 장바구니 이탈자를 같은 메시지로 운영하지 않는다.
- ROAS 외에 신규 고객 비중, 상품별 마진, 재구매와 환불을 함께 판단한다.

### 소액 예산 광고주

- 매체와 캠페인 목표를 분산하지 않는다.
- 가장 중요한 행동 1개를 정하고, 광고 세트와 소재 수를 줄여 판단 가능한 표본을 만든다.
- 예상 전환 수가 너무 적으면 전환 최적화를 확정적으로 약속하지 않고 트래픽·리드폼 등 현실적인 1차 검증 목표를 제시한다.

## 11. 제안서 문장 예시

- “본 캠페인은 클릭 수 확대보다 상담신청 완료를 최적화 대상으로 설정합니다. 웹사이트 양식 제출 이벤트가 정상 수집되는지 확인한 뒤 집행합니다.”
- “관심사 타겟은 실제 직업이나 구매 의도를 보증하지 않으므로, 초기 반응 데이터를 확인한 뒤 방문자·유효문의 기반 타겟으로 고도화합니다.”
- “자동 노출 위치는 예산 배분 범위를 넓히는 수단으로 사용하되, 지면별 전환율과 유효문의율이 낮은 구간은 별도로 점검합니다.”
- “Meta 광고 관리자에서 확인되는 문의 수와 실제 상담 가능 문의 수를 분리해 보고하며, 영업 결과를 다음 운영 판단에 반영합니다.”
- “릴스는 9:16 세로 영상과 안전 영역을 적용해 제작하며, Meta의 평균 사례 수치는 방향을 설명하는 참고값으로만 사용합니다.”

## 12. 제안서 확정 전 확인 목록

- 광고 목표와 실제 최적화 이벤트가 일치하는가
- 전환 위치와 랜딩 경로가 명확한가
- 픽셀·전환 API·앱 SDK·CRM 중 필요한 측정 수단이 준비됐는가
- 중복 제거와 테스트 이벤트 검증이 끝났는가
- 예산 대비 광고 세트와 소재 수가 과도하지 않은가
- Advantage+ 설정의 자동 확장 범위를 광고주에게 설명했는가
- 지면별 품질을 CTR만으로 판단하지 않는가
- 인스턴트 양식·메시지·전화의 유효성 평가 기준이 있는가
